Compressed Instructions, Intact Descriptions

Should a cost tool be allowed to rewrite what an agent reads?

200 real merged pull requests, replayed as agent tasks with and without /caveman-compress on skill bodies and memory files. Descriptions stay byte-identical. The claim is equivalence, with the margin fixed before any replay.

02 · the gap

Not whether compression hurts. Where.

Three results bracket the question. None of them measures activation in a real repository at the ratio a shipping tool actually achieves.

CompressAgent · arXiv 2608.01056
92.7%success at 75% retained context, against a 93.8% baseline. Generic rewriting reaches 19.9% at 35%.

Constructed control contexts, compressed to 35–50% of their tokens.

SkillRouter · arXiv 2603.22455
31.4–44.0 ppof Hit@1 lost when the skill body is removed, across sparse, dense and reranked retrievers.

The body carries routing signal. Descriptions alone are not the whole router.

SkillReducer · arXiv 2603.29919
+2.8%quality with 48% description and 39% body compression — because it adds selective restore.

Caveman compresses without repair. That difference is the study.

The measured premise changed. The pinned Engine returned 3,135 of 3,150 pool skill bodies byte-identical (99.5%), and 104 of 104 in the pilot. C1 is a small contrast, not a claimed 33% cut. The design reports that, rather than assuming the vendor's ratio.

03 · what the study claims

One primary claim, stated as a conjunction

H1 is equivalent only if both limbs clear their own 0.05-level test. Intersection–union keeps the joint size at ≤ 0.05 without a correction, and without an assumption about how activation and fidelity correlate.

H2 · memory routing. TV(C2, C0) ≤ 0.10 when at least two skills compete, read against the same replicate band. Secondary, Holm-corrected as its own family with H3.
H3 · positive control. C4 (~30% retained, no preservation rules) must reduce recall beyond the noise floor. If it does not, H1 and H2 are reported inconclusive — not equivalent.

05 · one replay

Seven steps, three gates, no second chance to be neutral

01FreezePR base.sha → tree tarball → throwaway root.
02Gate 0Installed set equals tree set, by bytes. Manifest verifies.
03ConditionC0–C4 applied only to the named surfaces. Ratio per file.
04CatalogName + description; body only on load_skill.
05ReplayTitle + body as untrusted data. 25 turns. Read-only tools.
06Gate 2Every call, activation with turn, tokens, termination.
07Gate 3Recall on pr_files; activation distribution.

What the agent sees

A catalog of names and descriptions, never a prompt full of bodies. Loading a body is the activation event and is recorded with its turn index. Dumping every body would destroy the thing being measured: which skill the agent chose to open.

What the agent never sees

The diff, the PR file list, or the branch name. The diff is the answer key Gate 3 scores against; showing it would turn recall into transcription. Context the body omits comes from the base tree with the tool surface.

Gate 0 · before spend

A three-skill canary proves disable-model-invocation first: hidden from the catalog, present on disk, not returned by an explicit request.

Gate 2 · during replay

Append-only JSONL after every turn. Hitting a turn or token ceiling is a recorded termination reason, not an exclusion.

Gate 3 · after replay

Every added or modified file in pr_files; removed files excluded. The numerator may come from the transcript, the denominator may not.

06 · instruments

Two instruments, 1,660 replays

One contrast, measured twice: once under a pinnable loop, once inside a real coding agent. The second is ecological generalisation, not a replication.

Why the second instrument is worth 460

It answers what the loop cannot: whether the measured effect survives a real agent, its own tool set and its own model. C0b on a pre-drawn 60 gives it a noise band of its own, because run-to-run variance in a real agent may exceed the scripted loop's.

Why not the full grid there

No hypothesis covers C2, C3 or C4 on the second instrument. C2's memory files reach a real agent through its own convention-loading, so that arm would measure the agent. The pty is also the least pinnable and most expensive path in the study.

07 · anchor and visibility

Tree-anchored. Nothing else reaches a replay.

The release is the frame, not the material. It supplies the sampling frame and the frozen stratum labels. No release byte enters materialisation, the catalog or any arm.
Visibility never edits the repository. Files stay byte-identical; a separate registry decides what the model can see. A repo skill Freebuff ships disabled is enabled there, not rewritten.
A mismatch stops the replay. The gate compares the installed set to the tree set in both directions, by bytes. There is no partial-set fallback, because a partial set changes what could have been activated.

08 · sample

The frame is 11.7× the sample

Both restrictions are eligibility rules on the frame, applied before the draw — not exclusions after it. Neither costs power.

Counted, never sampled

808 documentation-only pool PRs and 420 code PRs that add or edit a SKILL.md. The first would make size strata partly a code/not-code control; the second asks the agent to rewrite the artifact under test.

Still unmeasured: per-PR yield

A drawn PR enters only if its base tree holds at least one in-catalog skill. The rule is arm-invariant but can shrink n, and sample.jsonl carries no baseSha. Task 7c measures it before the prereg v2 hash.

09 · what the pilot measured

The treatment is real, and small

3,135 / 3,150pool skill bodies returned byte-identical by the pinned Engine — 99.5%
15changed; 14 of those violate the preservation contract
104 / 104pilot bodies byte-identical; invariant hashes equal in 14 of 14 PRs
Where the treatment actually lands99.5% untouched
3,135 untouched 15 changed → 14 violate

What the contract caught

Code fences (9), list items (6), identifier sets (4), inline code (3), emphasis lines (3). One clean compression survives, at ratio 0.991. Memory files: 365 files across 201 repos; 247 of 248 attempted came back identical.

The consequence that is still open

Any PR whose base tree holds one of the 14 violating skills drops from all arms, uniformly and in its own exclusion class. Whether that class is cosmetic or fatal is a measured question, not an assumption.

This is why C4 exists. When 99.5% of the treatment is a no-op, the destructive control is the only proof that the pipeline can separate at all — and the only thing standing between a null and a meaningless equivalence.

10 · inference

Why 10 points, and why no Holm

MarginPairsVerdict
10 pp172n = 200 → power 0.87
7.5 pp~3051.5× the draw and the spend
5 pp~686Out of budget; out of scope

n = (z₀₉₅ + z₀₀)² · p_disc / Δ²  ·  p_disc = 0.20

H1a gets its own power figure. A pre-registered simulation over base rate (0.1 / 0.2 / 0.3) × per-PR flip rate × catalog size, code and seed frozen before the hash.

Holm belongs to a disjunctive claim. Applied to two TOSTs it quietly turns each 90% CI into a 95% CI: power falls to 0.77, and ~211 pairs are needed merely to regain 80%.

The fallback is written, not chosen later. If fewer than 10% of C0 replays activate any skill, H1a is reported as uninformative by base rate and H1b alone carries the primary claim, at α = 0.05, unadjusted.

13 · review

What I want you to challenge

Q1

The judge is still in the gold set

Rev. 9 scores pr_files alone, but the delivered buildGold still takes neededSkillId and requires load_skill(neededSkill), so a model authors half the primary outcome. Task 11 marks the edit as required before any replay. Confirm it lands before v2.

Q2

H1a as a co-primary

It has no closed-form power. The prereg adds a simulation and a pre-declared fallback to H1b when the base-rate guard trips. Is a conditional co-primary acceptable, or should H1a be secondary from the start?

Q3

Tree coverage may cut n

Task 7c measures per-PR yield and the drop rate from the 14 contract violators. Run it before the v2 hash and accept a smaller n, or freeze n at 200 now and report attrition later?

Q4

460 replays on the second instrument

A C0b replicate on 60 PRs buys a noise band for an instrument that declares no equivalence. Is that worth the pty cost, or is the 400-replay C0/C1 contrast enough?

Not done yet: prereg v2 and its hash (blocked on Task 7c), the Task 7b registry and canary, and any live replay. Spec and plan rev. 9 are written but uncommitted.

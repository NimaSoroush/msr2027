02

Why this study, and why now

The literature has a hole exactly where shipping tools operate.

Teams adopt context-compression tools to cut agent cost. The strongest existing evidence says compressing an agent's control context becomes unreliable at aggressive ratios — but that evidence comes from constructed control contexts squeezed to 35–50% of their tokens, not from real repositories at the ratios shipping tools actually achieve. Whether compression changes what an agent invokes is unmeasured.

CompressAgent · arXiv 2608.01056

Reliability falls off a cliff — but where?

At 75% retained context, success is 92.7% against a 93.8% baseline. Methods diverge by 50% (37.8% vs 67.9%) and collapse at 35% (19.9%). LLMLingua preserved 0 of 9 pre-registered identifiers at every budget.

SkillRouter · arXiv 2603.22455

The skill body carries routing signal

Removing the body drops Hit@1 by 31.4–44.0 percentage points — not percent — across sparse, dense and reranked retrievers, and the effect survives length control. This is why we run two harnesses instead of assuming descriptions freeze routing.

SkillReducer · arXiv 2603.29919

Compression that repairs itself works

48% description / 39% body compression, +2.8% quality, 100% routing preservation — but only because it adds selective restore. Caveman compresses without repair. That difference is the study.

The gap is a narrow, defensible band. A ~33% token cut leaves ≈67% retained — inside the region prior work calls “close to baseline”, but below the ratios it actually certified (75%) and above where methods diverge (50%). So the honest question is not “does compression hurt agents”. It is “is activation preserved at the ratio real tools use?” — an equivalence question with a margin.
Measured 2026-11-18: the band is empty. On the 15 pilot PRs the pinned Engine returned 104 of 104 skill bodies byte-identical — every ratio 1.000, no token cut at all, against the 200/200 no-op the wider probe found. So the “≈67% retained” figure describes the prior work the design reasoned from, not what this pipeline achieves. Under the description-only harness a C0 and a C1 replay therefore see identical catalogs, and H1 has no manipulation to detect until the treatment changes. Recorded in docs/stage1-feasibility.md and spec §8.7 rather than left as a premise.

What we measure

Three hypotheses. The third exists so the first two can fail.
Primary H1

Activation is preserved when bodies are compressed

Tool-call recall with bodies compressed equals the uncompressed baseline within the margin.

C1 vs C0 · equivalence within Δ = 10 pp
90% CI must lie inside ±10 pp
Secondary H2

Routing is unchanged when memory files are compressed

When several skills compete, the distribution of which skill gets activated does not shift.

C2 vs C0 · total-variation distance ≤ 0.10
null band from the C0↔C0b replicate
Positive control H3

Destructive compression does break recall

If a deliberately destructive compressor cannot degrade recall, the pipeline is blind — and H1/H2 are reported as inconclusive, not as equivalence.

C4 (~30% retained, no preservation)
must show a drop larger than the noise floor

Pipeline

STAGE 1Sample200 PRs, stratified by repo skill-count and PR size. Pilot drawn from the complement, structurally disjoint.
STAGE 2MaterialiseFetch base tree, install skills from the release, discover memory files. Throwaway directory per replay.
STAGE 3CompressCaveman adapter, identity, or destructive control — applied only to the surfaces the condition names.

Layer ownership

Materialsrc/material/*
Turns one PR into a disposable working directory: base tree, skills at their recorded paths, memory files matched at any depth.
InvariantDescription, frontmatter and structure hashes are recomputed after materialisation, before any paid replay.
Compressionsrc/compress/*

InvariantCode fences, inline code, identifiers, headings, lists, tables and negations survive — or the file is rejected.
Replaysrc/replay/*
Tool surface, both harness catalogs, budgets, and an append-after-every-turn transcript writer.

Why the layering matters for approval. Each layer can be validated without paying for a model call: pagination against the real database, invariants against real skills, the contract against real compression. The only thing that costs money is the replay loop — and by the time it runs, everything it depends on is proven.
05

What happens inside one replay

Seven steps, three invariant gates. Same PR, five ways, in a fresh session each time.
  1. Freeze the material. PR base.sha → tree tarball → throwaway dir. Skills installed from the release at their recorded paths.
  2. Gate 1 — invariants. Descriptions, frontmatter and (path, name) pairs hashed. Any drift voids the replay before it costs anything.
  3. Apply the condition. C0/C0b untouched · C1 bodies · C2 memory files · C3 both · C4 destructive. Achieved ratio recorded per file; files under 10% reduction are flagged.
  4. Build the catalog. H1 shows name + description only; H2 shows full text. The catalog is asserted byte-identical across C0/C1/C2/C3 under H1 — the harness's own neutrality check.
  5. Replay. PR title + body, delimited as untrusted, never the diff — the diff is the answer key Gate 3 scores against. Context comes from the base tree, which the agent can list, read and search. Bodies too thin to state a before and after are screened out at sampling. Budget: 25 turns, fixed token ceiling. Shell recorded; read-only allowlist executes.
  6. Gate 2 — transcript. Every tool call with arguments, every activation with its turn index, tokens, ratios, termination reason. Appended to JSONL after each turn.
  7. Gate 3 — outcomes. Gold set from pr_files (files the PR actually touched) plus the annotated needed skill. Recall = intersection ÷ required.
The measurement that cannot be gamed

Gold sets come from the PR, never from the transcript

A required-call set derived from what the agent did would score 1.0 by construction and make every equivalence claim vacuous. So the required set is fixed by the merged PR's own changed files — the agent never sees them, and the treatment cannot inflate the denominator.

Two harnesses, because the literature disagrees

Description-only is primary; full-text is the check

SkillRouter shows bodies carry routing signal, so a description-only harness and a full-text harness can disagree about which skill wins. H1 runs the description-only catalog on all 200 PRs; the full-text catalog runs on 80. Divergence is a finding, not an inconvenience.

Safety

A stranger's PR text is data, not instructions

Prompt injection through a skill's bundled scripts is closed off by never executing repository code. Commands are logged for the transcript; only ls, cat, head, tail, grep and git status actually run.

07

The statistical case for 10 points

Two one-sided tests, α = 0.05 each — equivalently a 90% CI inside ±Δ.

Why not a tighter margin?

MarginPairs neededVerdict
10 pp172Affordable — n = 200 gives 0.87 power
7.5 pp3051.5× the pool draw, ~1.5× the spend
5 pp686Out of budget — declared out of scope, not promised
n = (z0.95 + z0.90)² · pdisc / Δ²
pdisc = 0.20 → 8.56 × 0.20 / 0.01 = 171.3 → 172 pairs

An earlier draft quoted 157 pairs — it applied a two-sided z to a one-sided TOST and understated the sample by ~15%. The corrected figure is the one in the protocol, and the report states the correction openly.

Why 10 points is the right question

Ten points is where a proxy stops being a proxy. Losing one tool call in ten is the threshold at which a cost tool should warn its user rather than stay silent — below it, the saving is real and the behavioural change is not practically detectable.

Reported before any contrast

The noise floor

C0 vs C0b gives the stochastic band. If it exceeds half the margin, H1 is reported on stable-baseline PRs only — and that restriction is stated, not discovered later.

Falsifiability

The positive control

C4 must degrade recall beyond the noise floor. If it does not, we report inconclusive. That pre-commitment is what separates this from a null result dressed as a finding.

Clustering is not optional. PRs within a repository share skills, conventions and reviewers, so observations are not independent. The 90% CI comes from a repository-clustered bootstrap (10,000 resamples), not a naive standard error.

Risks and how each is bounded

Every risk has a pre-committed response, not a hope.
RiskPre-committed responseSeverity
The control fails. Destructive compression does not degrade recall. The pipeline is not sensitive. H1/H2 are reported inconclusive, not equivalent. This is written into the protocol, so it cannot be renegotiated later. High
Model noise swamps the margin. The C0↔C0b replicate measures the band first. If it exceeds half the margin, H1 moves to stable-baseline PRs and the restriction is reported. Medium
Margin judged too wide. Answer with the power table: 5 pp needs 686 pairs. State the trade-off openly rather than promise a margin we cannot power. Medium
Material loss. Deleted repos, force-pushed branches. 20% oversample plus pre-specified, counted exclusions. The frame is 11× the requirement. Medium
Compressor drift. The Engine binary changes under us. Pin the release tag and sha256, record per-file transform hashes and the detect verdict, and keep the pre-compression bytes so any transform can be audited later. Medium
Ecological gap. The harness is a simulation, not a real agent session. A 15-PR bridge through Claude Code headless compares activation sets against our harness. Divergence is reported, not hidden. Low
Judge-labelled gold set. A model sets the answer key. An LLM judge from a different model family labels every PR blind to condition — GPT-6 Luna, run 2026-11-17 over all 200 PRs (75 need ≥1 skill) — with prompt and batches hashed; 20–30 human labels give κ. Mechanical rules are reported beside it and never gate, so a disagreement is visible rather than filtered. Low

Settled 2026-11-16. The served snapshot id goes into run_manifest.json and is quoted in the report, so the exact instrument is auditable. One model anchors every replay; no cross-model comparison is claimed.

Confirmatory, not exploratory

Equivalence with a fixed margin and a pre-specified analysis is a confirmatory hypothesis. The abstract's “Exploratory” label is a miscategorisation we are correcting before submission.

Δ = 10 pp · n = 200 · 1,200 replays

Powered at 0.87 against the 0.80 requirement. Tighter margins are declared out of scope rather than underpowered.

Six conditions incl. noise floor and control

C0b and C4 are exactly the “outcome-neutral tests” the call asks reviewers to score. Without them an equivalence claim is unfalsifiable.

Shell recorded, not executed

Ethics and prompt-injection safety in one decision: no repository code runs, so no skill payload can act on the host.

Pilot disjoint from the analysis sample

Drawn from the complement and removed before the analysis draw, so the split is structural rather than a checked promise.

GitHub token in place, read-only

Settled 2026-11-16. A fine-grained token with Contents: Read and Pull requests: Read on public repositories, verified against both required endpoints and never written to an artifact. No base trees exist without it, since SpecMine's PR layer carries neither base_sha nor PR bodies.

Single-anonymous review

The Author Guide asks for named authors and states single-anonymous review, contradicting an older double-blind assumption. Settled on the Guide's wording; if the call changes, it is logged as a deviation.

Second rater is an LLM judge

Settled 2026-11-16. A judge from a different model family than the study model re-codes the 50 blinded transcripts and labels the needed skill for every analysis PR, blind to condition, with its prompt and snapshot hashed in the prereg. The label round is done (GPT-6 Luna via the Freebuff CLI, 200/200 PRs valid); a mechanical cross-check runs on every PR and is reported, not gating — the path rule fires 0/200 on this frame and the body-path rule 32/200 — and 20–30 human labels, now drawn as 25 PRs, give the judge a κ to report against.
